# Модель учётных данных и перерасчёта

**Статус:** проект модели для ревью в PR. Согласованные правила отмечены отдельно от открытых решений; документ не утверждает бухгалтерские правила, которые владелец ещё не выбирал.

## 1. Принцип модели

Сервис хранит исходные операции и факты источников данных. Остатки, себестоимость, расчётный денежный баланс, прибыль и предварительные показатели вычисляются из текущих записей при запросе. Итоговые суммы не становятся отдельным источником истины и не должны оставаться устаревшими после исправления или прямого удаления исходной записи из PostgreSQL.

Поля финансовой или складской операции хранятся отдельно от их влияния на итоги. Например, API-строка Ozon может быть сохранена для сверки, но пока артикул не сопоставлен, она не изменяет остатки и денежные итоги согласно ТЗ.

## 2. Кандидаты сущностей

| Сущность | Какие исходные данные хранит | Производный эффект |
| --- | --- | --- |
| Товар | Внутренний артикул, название, категория, состояние архива | Ключ для группировки остатков, себестоимости и истории |
| Идентификатор товара Ozon | Связь внутреннего товара с `offer_id`, Ozon SKU и другими используемыми идентификаторами | Сопоставление строк заказов, возвратов и финансовых данных с товаром |
| Решение по неизвестному ID | Внешний ID и выбранное владельцем действие: сопоставить, создать товар или игнорировать | Сохранённое поведение последующих синхронизаций без повторного запроса и без дублей |
| Закупка | Дата, поставщик/источник, заказанное количество, стоимость и внесённая сумма | Внесённая сумма уменьшает расчётный денежный баланс; заказанное количество само по себе не создаёт остаток |
| Приёмка закупки | Ссылка на закупку, дата, фактически полученное количество и стоимость полученной партии | Увеличивает остаток продавца и входит в среднюю закупочную себестоимость |
| Поставка на Ozon | Дата создания, состав товаров, количество по каждой позиции, расходы доставки | Сразу перемещает количество продавец → Ozon; доставка уменьшает расчётный денежный баланс и участвует в общем коэффициенте один раз |
| Общий расход | Дата, сумма, категория и описание | Уменьшает расчётный денежный баланс и участвует в общем коэффициенте затрат согласно ТЗ |
| Отправление/заказ Ozon | Внешние ID заказа и отправления, товарные позиции, статусы и даты | Доставленное количество уменьшает остаток Ozon; предварительные и подтверждённые продажи рассчитываются отдельно |
| Начисление Ozon | Внешний ID/тип начисления, дата, сумма, валюта и связь с отправлением/товаром, если она есть | Формирует выручку, комиссию, логистику или корректировку по классификации Ozon; повторная синхронизация не повторяет эффект |
| Возврат Ozon | ID возврата, связь с исходным заказом/отправлением, тип, статус, текущая и целевая локации, количество | Сам факт возврата не меняет остаток; эффект зависит от места возврата и подтверждённого события |
| Списание Ozon | Внешний ID, товар, количество, причина, компенсация и её состояние | Уменьшает остаток Ozon; подтверждённая компенсация отражается как реализация по сумме компенсации, с защитой от повторного учёта в начислениях |
| Ручное списание продавцом | Товар, количество, дата и комментарий | Уменьшает остаток продавца. Влияние на прибыль пока не согласовано и остаётся открытым решением |
| Инвентаризация | Дата, склад, товар, ожидаемое и фактическое количество, комментарий | Фиксирует расхождение; изменение остатка появляется только после отдельного решения по этой инвентаризации |
| Решение по инвентаризации | Ссылка на пересчёт, тип и количество утверждённой корректировки | Создаёт отдельную исходную корректировку, которую можно увидеть и удалить/исправить |
| Сценарный расчёт | Параметры калькулятора и его результат | Показывается отдельно и не меняет операции, баланс, остатки или фактическую прибыль |

Это логическая модель, а не окончательные имена или нормализованная схема таблиц PostgreSQL. Детали хранения сырого API-ответа, связей удаления и допустимого редактирования требуют проверки при проектировании схемы.

## 3. Производные величины

### 3.1. Остатки

Остаток продавца и остаток Ozon рассчитываются как сумма складских движений по каждой позиции товара:

- **Склад продавца:** фактически принятые закупки − созданные поставки − ручные списания + возвраты, фактически полученные продавцом + отдельно утверждённые инвентаризационные корректировки.
- **Склад Ozon:** созданные поставки − доставленные покупателю количества − списания Ozon + возвраты, снова доступные к продаже на Ozon + отдельно утверждённые корректировки.

Создание заказа, его путь к покупателю, отмена до доставки и отказ до доставки не создают складское движение. При возврате продавцу не нужно второй раз уменьшать склад Ozon: он уже был уменьшен при исходной доставке. Возврат добавляется на склад продавца только после фактического получения.

### 3.2. Закупочная и полная себестоимость

- Средняя закупочная цена равна стоимости фактически полученных партий, делённой на суммарное принятое количество. Неполученная часть закупки не входит ни в числитель, ни в знаменатель.
- Коэффициент дополнительных затрат по ТЗ равен `(общие расходы + расходы доставки поставок) / стоимость фактически полученных закупок`.
- Полная себестоимость единицы рассчитывается с применением этого коэффициента к средней закупочной цене.
- Удержания Ozon по заказу не входят в общий коэффициент: они хранятся отдельно и учитываются по соответствующей продаже.
- Стоимость поставки и общий расход не уменьшают прибыль повторно отдельной строкой, если уже распределены через коэффициент себестоимости.

При нулевой стоимости полученных закупок деление на ноль запрещено; отображение полной себестоимости для такого товара требует явного состояния «нет базы для расчёта», а не придуманного нуля или значения по умолчанию.

### 3.3. Денежный баланс и прибыль

- Расчётный денежный баланс включает внесённые закупки, общие расходы, доставку поставок и признанные финансовые операции Ozon. Он не равен банковскому остатку и не принуждается к совпадению с прибылью.
- Обычные доставки младше 21 дня показываются как предварительные и не входят в основные суммы. Срок отсчитывается от даты доставки покупателю.
- По истечении 21 дня продажа и относящиеся к ней начисления/удержания входят в основные расчёты; поздние возвраты и корректировки пересчитывают их по данным Ozon.
- Выкуп маркетплейсом признаётся по финансовому отчёту Ozon. Сумма и удержания должны быть связаны с исходными ID так, чтобы данные отправления и отчёта не создавали два эффекта.
- Расчёт прибыли использует признанную выручку, себестоимость проданного товара, индивидуальные удержания Ozon и распределённые общие затраты. Это отдельная величина от движения денег.
- Влияние ручной потери на прибыль не задано до ответа владельца. Нельзя повторно вычитать стоимость товара из денежного баланса: закупка уже уменьшила его при внесении.

## 4. Сценарии перерасчёта

| Сценарий | Ожидаемое изменение исходных фактов | Проверяемый итог |
| --- | --- | --- |
| Закупка внесена, товар ещё не пришёл | Есть закупка и внесённая сумма; приёмки нет | Денежный баланс уменьшен на сумму закупки; склад продавца и средняя цена не изменились; ожидаемое количество видно отдельно |
| Частичная приёмка | В закупке заказано несколько единиц, принято только часть | На склад продавца добавлено только принятое количество; средняя цена рассчитана по принятым партиям; остаток закупки остаётся ожидаемым |
| Удаление приёмки | Физически удалена исходная запись приёмки | Следующий запрос пересчитывает склад и среднюю цену по оставшимся приёмкам; устаревшего сохранённого итога нет |
| Поставка создана | Указаны товарные позиции, количества и доставка | Количество перемещено продавец → Ozon; стоимость доставки уменьшила расчётный баланс один раз и входит в коэффициент один раз |
| Поставка удалена после дальнейших операций | Физически удалена поставка вместе с её строками | Следующий расчёт не использует её перемещение или доставку; если склад Ozon стал отрицательным, отрицательное значение показывается как ошибка сверки |
| Общий расход внесён | Создана одна запись расхода | Денежный баланс уменьшен один раз; вклад расхода в себестоимость идёт по общему коэффициенту, а не повторным списанием прибыли |
| Заказ создан или отменён до доставки | Обновился статус, доставка покупателю отсутствует | Остатки и основные денежные итоги не изменились |
| Заказ доставлен | Зафиксирована дата доставки и товарная позиция | Остаток Ozon уменьшен; до истечения 21 дня денежный баланс и фактическая прибыль не меняются, предварительные показатели видны отдельно |
| Предварительная продажа достигла срока признания | Истёк срок 21 день от доставки, получены финансовые данные Ozon | В основные итоги включены продажа и её фактические начисления/удержания; все строки связаны с одним внешним отправлением без дублей |
| Возврат доставленного товара на Ozon | Ozon показывает товар снова доступным к продаже | Остаток Ozon увеличен один раз; финансовая корректировка связана с исходной продажей |
| Возврат товара продавцу | Возврат ожидает выдачи, затем владелец подтверждает получение | До подтверждения склад продавца не меняется; после подтверждения добавляется количество, без повторного уменьшения Ozon |
| Списание Ozon с предварительной компенсацией | API сообщает `PRELIMINARY_COMPENSATION` | Количество отражается по подтверждённому событию списания; предварительная компенсация не признаётся как завершённое денежное поступление |
| Списание Ozon с закрытой компенсацией | API сообщает подтверждённую компенсацию и сумму | Товар отражён как списанный; компенсация учтена как реализация по сумме Ozon ровно один раз |
| Ручная потеря товара | Владелец создаёт ручное списание со своего склада | Остаток продавца уменьшается; повторного денежного расхода нет. Влияние на прибыль остаётся открытым до согласования правила |
| Инвентаризация выявила расхождение | Зафиксировано ожидаемое и фактическое количество | Создаётся расхождение для разбора; остаток автоматически не корректируется |
| Удаление исходной строки непосредственно из БД | Удалена запись, участвовавшая в расчёте | Следующий расчёт отражает оставшиеся записи, а не прежнее сохранённое значение |
| Повторная синхронизация Ozon | Те же внешние отправления/начисления загружены повторно | История источника может обновиться, но складской и денежный эффекты не дублируются |

## 5. Открытые решения

1. **Ручная потеря и прибыль.** Подтверждено, что товар уходит со склада продавца; не подтверждено, уменьшает ли такая потеря расчётную прибыль на полную себестоимость с коэффициентом. Нужно определить это до реализации соответствующего расчёта.
2. **Физическое удаление связанных данных Ozon.** До проектирования таблиц определить, как удаление нормализованной операции влияет на сохранённые исходные ответы Ozon и несопоставленные события. Любые остаточные строки не должны продолжать менять итоги незаметно.
3. **Подтверждение возврата на склад Ozon.** По живым примерам определить точный статус/сигнал доступности товара и связь с исходной доставкой.
4. **Списания и финансовые корректировки.** Проверить на реальных ответах, как связать закрытую компенсацию с финансовым начислением, чтобы избежать пропуска или двойного признания.
5. **Нулевой знаменатель себестоимости.** Утвердить текст интерфейса для товара без фактических приёмок; расчёт не должен подменяться фиктивным значением.

Эти вопросы не мешают зафиксировать логическую модель и проверить уже согласованные сценарии, но соответствующие ветки поведения нельзя объявлять окончательно согласованными или кодировать до проверки.
