# Gena

Локальный open-source сервис управленческого учёта для продавца Ozon по схеме FBO. Цель проекта — заменить рабочую таблицу одним приложением, где каталог, закупки, остатки, поставки, продажи, возвраты, расходы и итоговые расчёты связаны между собой и имеют понятную расшифровку.

Сервис рассчитан на одного пользователя и один кабинет Ozon. Он запускается на компьютере владельца в контейнерах, хранит базу и резервные копии локально и обращается к Ozon только для получения предусмотренных данными API сведений. Доступ к сайту из внешней сети не требуется.

Это управленческий учёт, а не замена бухгалтерской или налоговой отчётности. Расчётный денежный баланс показывает внесённые расходы и учтённые операции Ozon до фактической выплаты; он не является банковским остатком.

## Правила, на которых строится сервис

- Товары можно вести в универсальном каталоге с внутренними артикулами и идентификаторами Ozon.
- В остаток и среднюю закупочную себестоимость входит только фактически полученный товар. Внесённая стоимость закупки уменьшает расчётный денежный баланс сразу.
- Сервис отдельно считает склад продавца и склад Ozon. Ручная поставка сразу перемещает товар между ними; удаление поставки убирает её эффект.
- Заказ уменьшает остаток Ozon после доставки покупателю. Обычные доставки младше 21 дня показываются как предварительные; выкуп маркетплейсом учитывается по финансовым данным Ozon.
- Возврат на склад Ozon возвращает товар в остаток, когда он снова доступен к продаже. Возврат продавцу попадает на его склад только после фактического получения.
- Денежный баланс, прибыль, себестоимость и остатки выводятся из исходных операций. Они не хранятся в виде самостоятельных итоговых чисел.
- Повторная синхронизация не должна создавать дубликаты. Для каждого показателя должна быть доступна расшифровка.

## Состояние проекта

Технический стек первой версии выбран: TypeScript, React и Next.js, PostgreSQL и Drizzle ORM. Требования и архитектурный план проходят обсуждение в pull request; разработка приложения ещё не начата.
